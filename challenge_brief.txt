1 The challenge
Citizens keep asking the same practical questions: how much does it cost, which documents do I
bring, who can apply, what if I lost it? The answers exist in official service pages, but those pages are
messy Arabic text full of conditions and exceptions.
Your job: build a chatbot that answers these questions correctly, only from the documents we give
you, using the small model we provide through Ollama. Any approach and any tools are allowed.

3 What makes it hard
Look-alike services
The four passport files share most of their text. So do
the family book and ID card files. Often only one fee,
one document or one note is different. If your bot
picks the wrong file, its answer looks perfect and is
still wrong.
Fees depend on the person
Many fees are not one number: they change with age,
whether the document has expired, inside or outside
Jordan, how many times it was lost. Users describe
their situation; the bot must apply the right rule.
Facts hide in "notes"
Extra charges, deadlines, waiting periods and
exceptions are often under ﻣﻼﺣﻈﺎتnot under fees or
conditions.
People write in dialect
Users say اﻟﺒﺎﺳﺒﻮر ,اﻟﻬﻮﻳﺔ ,اﻫﱰى ,ﺷﻮ ﺑﻠﺰﻣﲏ؟ ,ﻗﺪﻳﺶ ﺑﺪﻓﻊ؟,
while the files say ﺟﻮاز اﻟﺴﻔﺮ ,اﻟﺒﻄﺎﻗﺔ اﻟﺬﻛﻴﺔ ,ﺑﺪل ﺗﺎﻟﻒ,
اﻟﻮﺛﺎﺋﻖ اﳌﻄﻠﻮﺑﺔ ,اﻟﺮﺳﻮم.
The data is messy
Website menu lines, tabs and blank lines, three
numbering styles, typos, repeated lines, copy-paste
leftovers, and amounts written as digits in one place
and as words in another. Clean it any way you want,
but don't change the facts.
A small model has limits
A 7B model makes reasoning mistakes and may
"remember" outdated facts from training. Ollama's
default context window is small, and text beyond it
can be cut off without any error. Answers must come
from the documents.
Knowing when not to answer
Some questions are not covered by the 12 files, including services that sound related but aren't in your data. A good
bot says it doesn't have that information instead of inventing an answer. When a question is unclear, a good bot asks
what the user means.

5 What we will run
Build your chatbot any way you like. For the evaluation we only need one thing: a main.py that reads a
questions file and writes an answers file.
1 Your project folder has a main.py. We put our questions.json next to it and run:
$ ls
data/   main.py   questions.json   # + any other files and folders your project needs
$ python main.py questions.json
main.py is only the entry point. Organize the rest of your project however you like (other modules, cleaned
data, indexes, config files).
2 When it finishes, a new file answers.json is in the same folder. That file is what we score.
$ ls
answers.json   data/   main.py   questions.json   # + your other files

Chats with several messages (bonus)
Answer the messages of a chat in order. A later message can depend on earlier ones: in chat-02 above,
"وﺑﻘﺪر أﻗﺪّم اﻟﻄﻠﺐ ﻣﻦ اﻟﺴﻔﺎرة؟means the family book renewal from the message before.
Every chat is a new user: forget everything from the previous chat.
These count as bonus: they add points and never lower your main score. No time for memory? Answer each
message on its own; you only miss part of the bonus.
Our scoring is automatic, so the format must be exact
Copy the structure. Keep chats, chat_id, messages, message_id and question exactly as you
received them, and add answer and contexts to every message. You may add other keys of your own;
we ignore them.
Answer every message, even if your bot fails on it. A missing answer scores zero.
The file must be named answers.json, in the same folder, valid JSON, saved as UTF-8.
Your program must work for any number of chats and messages. The real file is much bigger than the
practice one.
Common mistakes to avoid
Mistake What to do
Crash on Windows when reading or writing
Arabic text
Always open files with encoding="utf-8", e.g.
open("answers.json", "w", encoding="utf-8").
Works with internet, fails in the evaluation Before the run, download everything: ollama pull <model>, any
embedding models, pip packages. Then turn Wi-Fi off and test once.
Program needs a virtual environment Tell us the exact command, e.g. .venv/bin/python main.py or
venv\Scripts\python main.py.
One error stops the whole run and no file
is written
Catch errors per message and still write an answer, e.g. "answer":
"error". A partial file scores much better than none.
Very slow: each answer takes minutes The real file has many questions. Keep prompts and answers short,
check Ollama's context size, and time your program on the practice file.
Answers in the wrong place Write answers into the same chat and message they belong to. Never
reorder or merge chats.
Test it yourself
You get questions.json (5 chats, one with 2 messages) and answers_example.json with correct answers for
them. Run python main.py questions.json and compare your answers.json with the example: the structure
must be the same. Your wording can differ.

6 How you are evaluated
Every team gets the same hidden questions. Each answer is compared with a reference answer written from the
documents.
Criterion What we look for
Correct answer The right amounts, documents and conditions for the user's situation, with nothing wrong
added. Out-of-scope questions are declined; unclear ones are clarified. This matters most.
Right source The contexts you return come from the service(s) the question is about. We recognize this
from the text itself, cleaned or not.
Grounded answer What the answer says can be found in your contexts. An answer from the model's
memory counts as unsupported, even if it's right.
Answer the question that was asked. Pasting a whole document is not an answer. You'll also give a short
walkthrough of your solution: how you handled the data, how your bot finds the right information, and how you
stop it from making things up.
Rules
Use only the provided files as the knowledge source.
Every answer must be generated by the provided model when your program runs. No pre-written
answers, and no other AI models or online AI services.
You may use any tools while building, including AI coding assistants, and you may clean and
restructure the data, but not change its facts. Local helper models (embeddings, rerankers) are
allowed.
We run python main.py questions.json on your laptop with the internet off. Download the model
and every package beforehand. If your program needs a different command, tell us before the run.
